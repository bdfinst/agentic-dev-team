# Skill Templates and Registration

> **Agent templates live with `agent-create`.** The canonical agent file structure (review and team) is generated by the `agent-create` skill (invoked by `/agent-add`). Do not hand-author agent files — the schema is enforced by `/plugin-audit` and hand-authored files have historically drifted.

## Skill Template

```markdown
---
name: skill-name
description: When to trigger this skill and what it does. Be specific about the contexts that should cause an agent to invoke it.
role: worker
user-invocable: true
---

# [Skill Name]

## Overview
[1-2 sentences: what this skill covers and why it matters]

## Core Concepts
[Key terminology and mental models needed to apply this skill]

## Patterns
[Named patterns with descriptions, when to use, and examples]

## Project Structure (if applicable)
[Directory layout or file organization this skill implies]

## Guidelines
[Actionable rules for applying this skill correctly]
```

### Skill Authoring Guidelines

- Skills must be agent-agnostic: no references to specific agent personas or behaviors
- Write in imperative/instructional tone, not persona-driven
- Include "when to apply" vs. "when not to apply" guidance to prevent over-application
- Use tables for decision matrices (situation -> approach)
- Include project structure templates when the skill implies a file organization
- Keep skills focused on a single cohesive topic; split broad topics into multiple skills

## Registration Checklist

After creating an agent or skill, update all of the following. Incomplete registration leaves the system in an inconsistent state.

In the steps below, `$PLUGIN` refers to the target plugin directory (resolved as:
`--plugin <dir>` argument; else single `plugins/*/`; else cwd ancestor containing
`.claude-plugin/plugin.json`; else ask) and `$NAME` is the `name` field from
`$PLUGIN/.claude-plugin/plugin.json`.

### For a New Agent (Review or Team)

Use `/agent-add` — it invokes the `agent-create` skill, which handles all registration steps automatically:

- Writes the agent file at `$PLUGIN/agents/<name>.md`
- Validates against `/plugin-audit`
- Appends a row to the matching table in `$PLUGIN/knowledge/agent-registry.md` (if the file exists)
- Updates the Quick Reference list in `$PLUGIN/CLAUDE.md` (if the section exists)

For review agents specifically, also add eval fixtures to `evals/$NAME/fixtures/` and expected results to `evals/$NAME/expected/` at the repo root (these are not auto-generated; eval fixtures live outside the plugin directory).

For team agents, also update any team-structure or org-chart documentation the plugin maintains (if `$PLUGIN/docs/team-structure.md` or equivalent exists).

### For a New Knowledge Skill

1. Add to the **Skills Registry** in `$PLUGIN/knowledge/agent-registry.md` (if it exists)
2. Add to the Quick Reference Skills list in `$PLUGIN/CLAUDE.md` (if it exists)
3. Add to the appropriate section of `$PLUGIN/docs/skills.md` (if it exists)
4. Reference it from each relevant agent's `## Skills` section with invocation context

### For a New User-Invocable Skill

1. Add to the **Skills Registry** table in `$PLUGIN/CLAUDE.md` (if it exists)
2. Add to the appropriate section of `$PLUGIN/docs/skills.md` (if it exists)
3. Add a row to the relevant table in `README.md` if user-facing

## Documentation Sync Policy

**Every change to a plugin must be reflected in its documentation.** The general pattern:

1. **Hook** — if the plugin ships a doc-sync hook, it fires on every Edit/Write and emits targeted doc sync reminders
2. **Commands** — `/agent-add` and `/agent-remove` include mandatory documentation update steps
3. **Orchestrator Phase 3 gate** — tech-writer (or equivalent) reviews all affected docs before task completion

The source-of-truth table below describes the general pattern; adapt paths to the actual files your plugin maintains:

| Change type | Source of truth | Must match |
|---|---|---|
| Agent files | `$PLUGIN/CLAUDE.md` agent tables (if present) | `$PLUGIN/docs/agent_info.md` tables + `README.md` (if present) |
| Skills (user-invocable) | `$PLUGIN/CLAUDE.md` Skills Registry table (if present) | `$PLUGIN/docs/skills.md` User-Invocable Skills Catalog + `README.md` (if present) |
| Model routing | `$PLUGIN/knowledge/model-routing.json` (if present) | `$PLUGIN/CLAUDE.md` Model Routing pointer + architecture docs (if present) |
| Team structure | `$PLUGIN/docs/team-structure.md` diagrams (if present) | Actual agent files in `$PLUGIN/agents/` |
| Behavior/workflow | Orchestrator agent Phase workflow (if present) | `README.md` Workflow section (if present) |
| Architecture | `$PLUGIN/docs/agent-architecture.md` (if present) | `README.md` architecture section (if present) |
| Config/setup | `$PLUGIN/settings.json` + hook scripts | Architecture docs Governance section (if present) |
