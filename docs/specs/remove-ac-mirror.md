# Spec: remove the AC mirror from `/plan`'s Build Progress template

**Format:** dev-team specs v1
**Issue:** <https://github.com/bdfinst/agentic-dev-team/issues/526>

## Intent Description

`/plan`'s template today renders two kinds of checkboxes inside its `## Build Progress` section:

- **Slice + step checkboxes** carry real work-tracking semantics: they mirror `### Slice N: title` headings elsewhere in the plan, those headings have a `**Files:** ...` line the file-path commit matcher (from #525) consumes, and each step has a TDD RED→GREEN→REFACTOR block plus a draft commit message. `[x]` on a slice/step means "I committed code that touched the declared files."
- **An `### Acceptance Criteria` mirror** duplicates the plan's top-level `## Acceptance Criteria` list as `[ ]` items with the same headers. Those mirror items have **no** `### AC N:` heading, no `**Files:**` line, no commit message, and no way for the guardian to verify them. `[x]` on a mirror item means only "the operator ticked a box."

The pre-#525 guardian confused the two categories. The #525 fix skipped the H3 mirror block at `parse_plan` time so the guardian stopped false-positiving, but the mirror itself remained — silently ticked at build-end, giving false confidence that ACs had been verified. The user chose the simplest structural resolution: **remove the mirror entirely**. Acceptance Criteria live only in the top-level `## Acceptance Criteria` section as PR-checklist material — an operator ticks each one at PR review time after behaviorally verifying it, never at build time. The #525 guardian workaround stays in place as belt-and-suspenders for any legacy plan that still carries the old shape.

## Architecture Specification

**Files edited (3):**

1. **`plugins/dev-team/skills/plan/SKILL.md`** — remove the `### Acceptance Criteria` subheading and its example bullets from the `## Build Progress` template block (lines 215–219 today). Update Step 4's prose (line 224) to stop mentioning "criteria from `## Acceptance Criteria`" — Build Progress mirrors only slices + steps.
2. **`plugins/dev-team/skills/build/SKILL.md`** — remove the sub-bullet at line 119 that instructs `/build` to tick items in the Build Progress `### Acceptance Criteria` subsection as steps complete. `/build` stops auto-ticking ACs. Operators tick them post-merge (or during PR review) after behavioral verification.
3. **`tests/repo/plan-template-tests.bats`** (new or extended) — one bats test asserting the `/plan` template block in `plan/SKILL.md` does NOT contain a `### Acceptance Criteria` subheading between `## Build Progress` and the next H2/H3-of-a-different-name. Existing bats fixtures under `tests/repo/` and `tests/scripts/` (particularly the guardian fixtures added in #525) continue to green because the guardian's inner `in_acceptance` skip fires on the presence of the subheading; its absence is a no-op fallthrough to the outer Build Progress scope.

**Behavior preserved:**

- The top-level `## Acceptance Criteria` section of every plan is unchanged. Every AC declared during `/specs` still lives there. It remains the single source of truth for what the change must satisfy.
- The guardian's #525 inner-skip logic (`in_acceptance` flag in `parse_plan`) stays. Legacy plans on branches that still carry the mirror do not break — the guardian silently skips the block. New plans generated by the updated `/plan` template will have no mirror, so the skip is a no-op fallthrough.
- Slice/step tracking, `**Files:**` file-path matching, and everything else about the Build Progress section is untouched.

**Explicit non-changes (rejected before spec-writing):**

- **No new verify-command mechanism.** Option 2 in issue #526 (per-AC verify commands the guardian runs) is a different, larger design; rejected by the user in favor of the simplest resolution.
- **No slice↔AC binding.** Option 3 rejected same way.
- **No evidence-required scheme.** Option 4 rejected same way.
- **The #525 guardian workaround stays.** The AC-skip in `parse_plan` is now defensive — it fires only on legacy plans. Not removed because it costs almost nothing and future third-party tools that generate plans in the old shape still get a graceful gate.
- **No retroactive edit of existing plans on `main`.** Plans in `plans/*.md` (from #524/#525/#531) that carry the old mirror are left alone. They're historical artifacts; touching them adds diff surface without benefit.

**Risk surface:**

- **Downstream tooling that reads the Build Progress AC subsection.** Verified during spec-writing: `grep -rn "### Acceptance Criteria" plugins/ scripts/ hooks/` returns no *code* references (only the skill-file template blocks themselves and the guardian's inner-skip regex). Removing the subsection from new plans is a pure prose change — no parser depends on its presence.
- **The `/build` fix loop.** Verified `plugins/dev-team/skills/build/SKILL.md` line 119 is the only site where `/build` interacts with the AC subsection. Removing that instruction leaves the rest of the fix loop unchanged.
- **`/continue` resume logic.** Reads Build Progress for slice/step state. Does not depend on AC checkboxes. No change needed.
